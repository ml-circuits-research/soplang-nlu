# Evaluation and labels

This page: why the project needed its own evaluation, the path of one circuit through the tools,
and the pages of this section. Kind: Explanation.

## The problem

The usual way to measure a parser is **standard**: compare its output with a tree that a person
annotated, word by word
([attachment scores](https://en.wikipedia.org/wiki/Syntactic_parsing_(computational_linguistics)#Evaluation)).
That does not work here, for two reasons:

- there was no annotated data for this [syntax schema](../schema/overview.md);
- several [circuits](../reference/glossary.md) can be right for one message, so a single reference
  would count right answers as wrong.

The project therefore built its own procedure. As a whole it is **new here**; its parts are
standard ideas: a [language model as a judge](judging.md), a [random sample](benchmark.md),
[agreement between independent sources](agreement.md) and [a control sample](audit.md).

In machine learning, a [label](https://en.wikipedia.org/wiki/Labeled_data) is the right answer
stored for an example. Here a **label** is the accepted circuit stored for a message in the
[dataset](dataset.md).

## The path of one circuit

Each step below names the *level* (L0 to L10) the circuit gets in the table of a run. The levels are
defined in [Levels L0–L10 and GOAL](levels.md).

1. A [formalizer](../formalizers/README.md) (the code says *strategy*) writes the circuit. When it
   writes no valid circuit, the message is at level L0.
2. The circuit is put in [normal form](normal-form.md) and its *core* is computed. Two circuits of
   one message are the same when their cores are equal.
3. If the circuit equals the label the message had before the run, it is accepted already: level
   L9, and no judge reads it.
4. If the *registry* (the folder that keeps every judge decision) already holds the circuit, it
   keeps that verdict.
5. In a conversion round only: if formalizers of enough different *families* wrote it alike,
   [agreement](agreement.md) settles it. A random share of these still goes to a judge
   ([the audit](audit.md)).
6. Otherwise it goes to a [judge](judging.md) in a *packet* (a file of circuits for one judge),
   with nothing that tells who wrote it.
7. Publication. A [benchmark](benchmark.md) makes every accepted circuit the label of its message.
   A [conversion round](conversion.md) only fills empty cells.
8. The table counts, per formalizer, how many messages stand at each level, and
   [GOAL](levels.md#goal): the share of messages whose circuit is accepted.

## Three ways a circuit is accepted

The `accepted_by` cell of a message's row in the dataset records which way:

| accepted_by | Meaning |
| --- | --- |
| `judge` | A judge read the circuit and accepted it. |
| `written` | A judge wrote the circuit, because no formalizer's circuit was accepted. |
| `agreement` | Formalizers that read the message from different sources wrote it alike; no judge read it. |
